# Supplementary Farmland Characteristics

## Why do we need additional farmland characteristics?

Land management decisions are plausibly influenced by physical, economic, and locational context beyond what Regrow/CSB/DISES capture directly — soil quality, terrain, weather, market access, nearby farming behavior, and crop prices. These 9 supplementary blocks attach that context to every Regrow/CSB field so it can be used as covariates in downstream analysis.

## What supplementary farmland characteristics are available?

| Topic | Source | Static or dynamic | Time coverage | Resolution |
| --- | --- | --- | --- | --- |
| Census tract/county/state boundaries | TIGER 2023 | Static | 2023 release | Tract-level polygons |
| Elevation & slope | USGS 3DEP | Static | Current 3DEP survey | 1 arc-second (~30m) |
| Watershed (HUC8/10/12) | USGS 3DHP / NHD | Static | Current NHD/3DHP delineation | Polygon (subbasin/watershed/subwatershed) |
| Roads (primary/secondary) | TIGER PRISECROADS 2023 | Static | 2023 release | Vector lines |
| Neighboring-field land management | Derived from Regrow/CSB itself | Dynamic | Same years as host dataset (Regrow: 2014–2025, CSB: 2017–2024) | Field-level, derived from the host dataset itself |
| Weather (PRISM) | PRISM AN Monthly | Dynamic | Monthly, 2014–2025 | 800m |
| Crop price (elevator & county) | Barchart (proprietary) | Dynamic | Monthly; price series with fewer than a configured minimum number of observations between 2015 and 2025 are dropped | Point-level (elevator) / county-level (index), spatially interpolated to fields |
| Soil composition | gSSURGO | Static | Current gSSURGO survey release | 30m (map-unit raster) |
| USDA Census of Agriculture (county-level) | USDA NASS QuickStats | Static | 2017 & 2022 Census of Agriculture | County-level (not field-level) |

"Static" means the dataset reflects conditions at a single point in time (e.g. one published survey/release), rather than tracking change over time. "2023 release" means the specific TIGER vintage published by Census in 2023 — i.e., the dataset as it existed at that one publication date, not a 2023 measurement of a changing quantity.

### What datasets are used to generate each supplementary block?

- **Census tract** — [Regrow script](../40-scripts/47-merge-regrow-supplements-scripts.md#join_regrow_census_tractpy) | [CSB script](../40-scripts/49-merge-csb-supplements-scripts.md#join_csb_census_tractpy): TIGER 2023 Cartographic Boundary Files. Each field is assigned to a census tract by computing the field's geographic **centroid** — a single representative point at the center of the field polygon — and testing which census tract polygon contains that centroid via a within-join. This centroid approach is used because testing point-in-polygon is much faster than computing the overlap area between the full field polygon and all tract polygons. Fields whose centroid falls outside all tract polygons (due to polygon precision near boundaries) are assigned to the nearest tract instead: the tract whose polygon is geographically closest to the unmatched centroid. Adds state, county, and census tract identifiers, and tract land/water area.

- **Elevation & slope** — [Regrow script](../40-scripts/47-merge-regrow-supplements-scripts.md#join_regrow_elevation_slopepy) | [CSB script](../40-scripts/49-merge-csb-supplements-scripts.md#join_csb_elevation_slopepy): USGS 3DEP 1-arc-second elevation rasters, clipped and reprojected to the project equal-area CRS (EPSG:5070), plus a slope raster derived from elevation via GDAL (degrees). For each field, the **zonal mean** is computed for both rasters: every raster pixel whose center falls inside the field polygon contributes to the mean. Adds `elevation_mean` (meters) and `slope_mean` (degrees) to each field.

- **Watershed** — [Regrow script](../40-scripts/47-merge-regrow-supplements-scripts.md#join_regrow_watershedpy) | [CSB script](../40-scripts/49-merge-csb-supplements-scripts.md#join_csb_watershedpy): USGS 3DHP/NHD hydrologic unit boundaries at three nested scales — subbasin (HUC8), watershed (HUC10), and subwatershed (HUC12). Each scale is processed independently: the field's geographic centroid is computed and tested against the watershed unit polygons at that scale via a within-join, assigning each field to the unit it falls inside. Unlike the census tract join, there is no nearest-unit fallback for unmatched centroids; fields whose centroid falls outside all boundaries for a given scale are left with missing values for that scale.

- **Roads** — [Regrow script](../40-scripts/47-merge-regrow-supplements-scripts.md#join_regrow_nearest_roadspy) | [CSB script](../40-scripts/49-merge-csb-supplements-scripts.md#join_csb_nearest_roadspy): TIGER 2023 PRISECROADS (primary + secondary roads). For each field, finds the nearest road segment by computing the minimum distance from the full field polygon boundary to any point on the road network. When more than one road is at equal minimum distance, the road with higher class priority (primary, MTFCC S1100, over secondary, S1200) is kept. Adds `dist_to_road` (Euclidean distance in CRS units, approximately meters) and `road_type`.

- **Neighboring-field land management** — [Regrow script](../40-scripts/47-merge-regrow-supplements-scripts.md#join_regrow_neighbor_field_mgmtpy) | [CSB script](../40-scripts/49-merge-csb-supplements-scripts.md#join_csb_neighbor_field_mgmtpy): Derived entirely from the host dataset (Regrow or CSB) itself — no external source. Neighboring fields are defined as any fields whose polygons share a boundary or overlap with a given field's polygon (spatial intersect self-join). For each field: **Regrow branch** — (1) the simple mean of each tillage and cover-crop practice code across all neighbor fields is computed for each cultivation-cycle column; (2) for each cultivation-cycle crop column, the area-weighted share of neighboring field acreage in each crop group (corn / soybean / wheat / other) is computed, where each neighbor is weighted by its field area in acres. **CSB branch** — crop-composition shares only (no tillage or cover-crop averaging, since CSB has no tillage or cover-crop columns).

- **Weather** — [Regrow script](../40-scripts/47-merge-regrow-supplements-scripts.md#join_regrow_weatherpy) | [CSB script](../40-scripts/49-merge-csb-supplements-scripts.md#join_csb_weatherpy): PRISM AN Monthly Time Series, 6 variables (precipitation, min/max temperature, mean dew point, min/max vapor pressure deficit), 2014–2025, 800m resolution. For each field and each monthly raster, the PRISM value is extracted at the field's geographic **centroid** — a single point sample at the center of the polygon, not a spatial average across the polygon. Column names use `_centroid_` to reflect this distinction. One column per variable per year-month is added to each field record.

- **Crop price** — [Regrow script](../40-scripts/47-merge-regrow-supplements-scripts.md#join_regrow_crop_pricespy--cut_regrow_crop_pricespy) | [CSB script](../40-scripts/49-merge-csb-supplements-scripts.md#join_csb_crop_pricespy--cut_csb_crop_pricespy): Barchart elevator-level monthly cash prices for corn/soybeans/wheat, and county-level monthly cash prices for corn/soybeans (no county series for wheat). A KD-tree is built over geocoded elevator (or county) locations in projected coordinates, enabling fast lookup of the N nearest price sources to each field's centroid. Two price series are computed per crop: (1) a distance-weighted average price across the N nearest sources, where each source's weight is its inverse Euclidean distance to the field centroid, applied over non-missing monthly observations only; (2) a gap-filled series starting with the nearest source, filling missing months from the 2nd nearest, then 3rd, etc. For county-level prices, the field's own county is always prioritized first in the neighbor list. The gap-filled single-nearest series is subsequently dropped, leaving only the N-nearest distance-weighted averages and the county-level series in the final reduced file.

- **Soil/gSSURGO** — [Regrow script](../40-scripts/47-merge-regrow-supplements-scripts.md#join_regrow_soil_compositionpy) | [CSB script](../40-scripts/49-merge-csb-supplements-scripts.md#join_csb_soil_compositionpy): gSSURGO (Gridded Soil Survey Geographic Database, USDA NRCS), 30m map-unit raster. Soil attributes are derived in two stages: (1) **map-unit level** — categorical attributes (`drainagecl`, `cropprodindex`, `resdept_r`) are taken from the **dominant soil component** of each map unit (the component with the highest percent composition); continuous attributes (sand, clay, pH, organic matter) are first depth-weighted across soil horizons within each component to a target depth of 0–30 cm (using horizon thickness as the weight), then component-weighted across all components within the map unit using percent composition as the weight; slope (`slopegraddcp`) is taken from the pre-aggregated muaggatt table; (2) **field level** — the field-ID raster (from `rasterize_regrow_to_gSSURGO_grid.py` / `rasterize_CSB_to_gSSURGO_grid.py`) and the mukey raster are read simultaneously; for every field-raster pixel belonging to a field, the corresponding mukey is recorded, giving the full set of map units present under each field's polygon footprint; numeric variables are then averaged and categorical variables take the mode across those map units.

- **USDA Census of Agriculture** — [Regrow script](../40-scripts/47-merge-regrow-supplements-scripts.md#join_regrow_ag_censuspy) | [CSB script](../40-scripts/49-merge-csb-supplements-scripts.md#join_csb_ag_censuspy): USDA NASS QuickStats county-level data from the 2017 and 2022 Census of Agriculture. Data items are read from four source files (land use, field crops, conservation practices, producer characteristics), covering farmland/cropland/pastureland/woodland acreage and ownership tenure, harvested acreage for corn/soybeans/winter wheat, conservation tillage and cover crop acreage, and producer demographic/decision-making characteristics. All items are stacked into a long table and pivoted to wide format — one row per county, one column per variable×census year. **Unlike the other supplementary blocks above, this is a county-level output, not a field-level one**: the table is keyed on `county_state_name` and covers only the counties present in that state's census_tract output. `county_state_name` is therefore the matching key to use when joining this block to any other data block that has a county/state identifier.
